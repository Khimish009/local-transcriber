# Changelog

Формат вдохновлён [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/). Записи — от новых к старым.

## [Unreleased]

### Added
- `python -m benchmark.equivalence` сверяет оптимизированную диаризацию со стоковым pyannote
  на записи из `benchmark.run` и завершается с ненулевым кодом при расхождении.
- Phase 12 — Performance в `TASKS.md`: пять ускорений pipeline на CPU, ни одно не должно
  менять результат. Исходный замер: запись 37 мин обрабатывается 22 мин, из них ~70% —
  эмбеддинги спикеров в диаризации.

### Changed
- Диаризация в 3 раза быстрее при том же результате: эмбеддинги спикеров считаются одним
  проходом ResNet на окно, а не тремя. На записи 37 мин — 1014 с → 339 с, спикеры и
  сегменты совпали со стоковым pyannote точно.
- `pyannote.audio` закреплён точной версией `4.0.7`: ускорение заменяет его внутренний метод.
- Предупреждение «Worker недоступен» (на главной и на странице задачи) появляется только
  после двух ответов `/health` подряд. Одиночный сбой проверки больше не пугает текстом
  «задачу придётся запустить заново».
- `AGENTS.md`: раздел «Current assignment» отмечает T11.2 сделанным, появился раздел
  «Документация» со ссылками на `docs/` и `CHANGELOG.md`.
- Время обработки считает сервер: в ответе `Job` появились поля `processing_seconds` и
  `processing_includes_queue`. UI их больше не пересчитывает, поэтому определение одно
  и покрыто тестами. В Redis эти поля не пишутся.

### Fixed
- Страница задачи предупреждает, если worker недоступен, и останавливает счётчик «Идёт X».
  Раньше счётчик рос бесконечно и выдавал зависшую задачу за выполняющуюся, а
  предупреждение было только на главной странице.
  Вместо длительности выводится время последнего обновления. Цифра включала бы весь простой
  после краха и при опросе продолжала бы расти.
- Около паритета UI больше не пишет «быстрее записи в 1.0 раза» или «медленнее в 1.0 раза»,
  а пишет «примерно за длительность записи». Дробная часть выводится через запятую.
- Для задачи, упавшей из-за краха worker, UI пишет «Остановилась не раньше чем через X»:
  это оценка снизу (см. запись про recovery ниже).
- На странице задачи нет пустого абзаца, пока строке о времени нечего сказать (задача в
  очереди). Секундный таймер тоже не запускается, пока задача в очереди.
- Список задач помечает «(вместе с очередью)» время старых записей. Раньше эта пометка
  была только на странице задачи, и цифры в списке и на странице расходились по смыслу.
- Задача, которая упала ещё в очереди, больше не показывает «Остановилась через N ч —
  вместе с ожиданием в очереди». Время у неё неизвестно, поэтому строка не выводится.
- Счётчик «Идёт X» не зависит от расхождения часов браузера и сервера: браузер прибавляет
  к серверному значению только время, прошедшее с момента получения записи.
- Больше не бывает «обработка NaN с»: время приходит с сервера числом.
- Recovery больше не засчитывает простой worker во время обработки: у упавшей задачи
  `finished_at` теперь равен её последнему обновлению, а не моменту перезапуска worker.
  Подробности — [docs/processing-time.md](docs/processing-time.md).
